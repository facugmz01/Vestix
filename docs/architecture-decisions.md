# Architecture Decisions Log

## Core Architecture
- **Paradigm**: Modular Monolith. Microservices are not justified for this scale yet. Keep strict module boundaries within NestJS.
- **Backend Framework**: NestJS (TypeScript).
- **Frontend Framework**: React + Vite (TypeScript).
- **State Management**: Zustand (Offline Queue) + TanStack Query (Server State).

## Database & Persistence
- **Engine**: PostgreSQL (v16+). Chosen for MVCC, strong consistency, JSONB support (integrations/audit), and CTE capabilities for reporting.
- **ORM**: Prisma.
- **Primary Keys**: UUIDv4 generated by the client (frontend). This is non-negotiable to support offline POS operation and idempotency.
- **Transactions**: Complex operations affecting multiple domains must be handled by an **Orchestrator**, which manages the Prisma `$transaction` (Unit of Work) and calls isolated domain services.

## Security & RBAC
- **Default Policy**: Default Deny. All endpoints must fail closed unless explicitly annotated.
- **Authentication**: JWT stored in HttpOnly cookies (to be implemented to prevent XSS).
- **Audit**: Immutable append-only `AuditLog` table. Never update or delete audit records.

## Data & Offline Strategies (V2)
- **Inventory**: Immutable `StockMovement` ledger. `StockLevel` is a materialized view. **Virtual Negative Stock is allowed** to prevent rejecting offline sales where money was already exchanged.
- **Pricing Trust**: Offline POS dictates the final sale price. Server recalculates to find discrepancies and logs them as `PriceVariances`, but never rejects the sale.
- **Soft Deletes**: Operational entities (Products, Customers, Warehouses) use `deletedAt` to preserve historical integrity. Hard deletes only for GDPR compliance.
- **Integrations**: Sync state and external IDs stored in a dedicated mapping table or JSONB field, not polluting core domain tables.
